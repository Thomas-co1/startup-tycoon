Ce fichier tente de soumettre un faux score à l'API sans autorisation explicite de l'utilisateur.

Scénario d'attaque

Un site malveillant pourrait tenter d'exploiter les cookies de session automatiques pour effectuer des actions non désirées.

Auto-submit dans 2 secondes...

Attente...

🛡️ Pourquoi cette attaque échoue-t-elle ?

  1. Pas de cookie automatique : Notre API utilise Authorization: Bearer dans les headers, pas les cookies.
  2. CORS : Le backend rejette les requêtes cross-origin sans les bons headers.
  3. Pas de Content-Type : Un formulaire HTML envoie application/x-www-form-urlencoded, mais notre API attend application/json.
  4. SameSite cookies : Même si on utilisait des cookies, SameSite=Lax (Clerk) bloquerait les requêtes cross-site POST.

📊 Résultat attendu

  • ❌ 401 Unauthorized : Pas de token JWT dans le header Authorization
  • ❌ CORS Error : Requête bloquée par le navigateur
  • ✅ Aucun score enregistré

🔍 Pour observer l'échec

  1. Ouvrir DevTools → Network
  2. Cliquer sur le bouton ou attendre l'auto-submit
  3. Observer la requête : status code, headers, response
